# 结果分析与方法复盘

模型：`qwen3.8-max-0902`；主评估 20 条，独立参考对比 20 条。全部结果均来自真实 API 已校验响应。最终生成报告时复用 40 条本地缓存，因此元数据中的“本次接口请求 0”表示这一次重建未重复付费调用，并不表示结果来自 mock。

首次主评估全部通过；参考对比最后一条出现结构字段不符合协议，程序拒绝该输出并退出。重运行复用了前 39 条合法结果，仅重新请求最后一条，通过校验后完成。随后重建报告均使用完整缓存。连接探测与失败请求未计入成功样本数量，报告 token usage 只统计当前进程的新成功调用，不是实验总消耗。

## 2. 整体发现

主要问题是解决问题的有效性不足，而非普遍缺乏礼貌。真实模型给有效性 60.0、语气 85.0；常见缺口是缺少具体商品、订单或操作卡点的信息确认。状态分布为 5 条可接受（暂定）、11 条需要改进、4 条高风险待复核。

29 个候选断言均缺少外部业务证据，所以事实维度全部弃权。这里不能写成“发现 29 处幻觉”。退款时效、质保、运费、补偿及平台功能应优先补来源。4 条高风险复核分别涉及明确流程冲突或未经证实的售后承诺；它们不全是已证实错误。

## 3. 最低分 3 条及排序局限

- **case_11：49 分。** 既要求退货后重新下单，又描述退件后发出换货，流程混淆；同时未确认两件商品及目标尺码。规则与 LLM 均识别了问题，触发总分上限。应先确认对象、尺码，再提供经核实的一种流程。
- **case_16：55 分。** 模型认为没有问清是哪两款手机，切题与有效性均给 2 分。但人工注释认可预算和场景追问基本合理。这个排名很可能偏严，应进入分歧复核，不能直接宣称它是客观第二差。
- **case_01：63.3 分。** 用户明确取不出来，仍被建议去错误柜取件，缺少具体处理闭环。应先确认取件障碍和必要信息，在真实能力范围内协助处理。

case_01 与 case_06、case_09、case_12 等存在同分；报告按 id 打破平分。这是展示排序规则，不是宣称同分案例存在确定的质量差距。完整原文、证据和模型理由见看板及 JSON。

## 4. 校准结果说明了什么

在 100 个潜在样本-标签对中排除 18 个未知对，实际纳入 82 个，其中正例 30 个。混合方案 TP=22、FP=15、FN=8、TN=37；这里的 FP/FN 仅表示相对当前复核标签的分歧。

### 缺少追问识别较好，但容易扩大范围

`missing_clarification` Recall=1.0、Precision=0.8。模型能发现缺少具体机型、退货原因等细节；但一些追问是可选增强，不能一律导致整条回复被判成严重服务缺口。

### 共情标签主观且误报较多

`insufficient_empathy` Precision=0.1667、Recall=0.3333。模型把普通退款、换货等场景也判为需要更多道歉，而原注释更关注明确情绪、敏感需求或连续受损。改善方向是先规定需要特殊安抚的触发场景，避免把“未道歉”普遍视作缺陷；再交给第二位标注者复核。

### “服务推进不足”与“缺少追问”存在边界重叠

同一不足可能被模型归入 `missing_clarification` 或 `generic_answer`，而复核标签归为 `passive_service`，产生标签级漏检。说明分类体系应明确多标签共现规则，不能只靠短标签名。

### case_20 的意图错配被漏掉

主模型认可流程及截图入口，把有效性评为 3，并未输出 `intent_mismatch`。人工注释认为用户已经操作困难，重复流程没有针对卡点。这是需要增加独立反例验证的关键场景，不应将主模型输出当作真值。

### 程序隔离不等于真正独立测试

复核标签来自开发者对已见注释的归纳，未提到的问题被整理为负例，会低估模型提出的合理额外问题；例如 case_01 的订单/柜信息追问是否必要本身存在争议。不能把所有 FP 直接称为模型错误。规则基线更贴近原注释，因此更高 F1 也不能证明更强泛化能力。

二元服务缺口任务纳入 16 条，真实混合方案 F1=0.6667，一致率 56.25%。这一任务把有效性分数阈值化，进一步放大了“轻微问题还是明显缺口”的量表边界差异。

## 5. 参考差异模块的独立价值

case_03 清楚展示了“通用退款时效”与“获取订单后核查”的差别；case_13 能指出人工参考存在 XX 成分占位符；case_01、case_15、case_16 的参考还包含未经核实的时效、补偿或权限假设。

成对分析也会出错。例如 case_16 的参考新增说明把“首页目前有几款手机”称作事实，但在同一输出的参考局限里又指出该信息没有被核实。保留原始结果并在此标注这一不一致；该模块应作为人工复核材料，不能作为自动改写政策的依据。

## 6. 本轮保留与下一轮修改

本轮没有在看到验证结果后修改标签、调低通过阈值或挑选最好一次模型输出来提高分数。保留混合架构与规则基线，明确系统已经工程闭环，但模型有效性仍待独立数据校准。

建议下一轮先冻结更细的标签手册与评分锚点，由两名人工标注者给新增样本打标签及数值分，划分开发集和保留集；再比较 prompt 版本，报告每次修改、全量结果、稳定性与调用成本。业务事实库应与人工参考严格分离，并使用版本化证据。
