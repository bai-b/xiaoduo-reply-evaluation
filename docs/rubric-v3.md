# v3 评价标准与标注手册

本轮修改评分判据及标签边界，**不修改原有复核标签**。完整运行量表见 `prompts/judge.md`，这是程序实际发送给模型的版本化标准。

## 回答业务方的六个问题

| 业务问题 | 操作性定义与量化方式 |
|---|---|
| 什么是准确？ | 分开衡量“理解对问题”和“外部事实正确”。前者用切题与内部一致性 0–4 分，依据诉求覆盖及流程矛盾；后者必须依赖订单、商品、政策或工具记录。不能把看起来切题当事实准确。 |
| 什么是有用？ | 看这轮回复能否推动当前问题解决：充分回答或必要澄清为4；有效路径但缺细节为3；核心卡点未解、只有通用帮助为2；几乎没有下一步为1；阻断解决为0。合理自助与追问都可以是有效行动。 |
| 什么是语气好？ | 尊重且符合情境：中性咨询自然礼貌即可为4；明确恐惧/反复受损等情境下回应不足为3或2；指责不耐烦为1；侮辱为0。不按道歉词的数量评分。 |
| 什么是不瞎编？ | 抽取可核查的事实断言，区分 supported、contradicted、unverified。全部有证据支持时事实分为4；存在矛盾为0；证据不足或无断言时N/A。同步报告断言证据覆盖率和高风险承诺，未核实不能直接称为幻觉。 |
| 指标优先级？ | 证实重大事实错误/明确流程冲突先门控，总分最多49；未经证实的高风险承诺先复核。正常融合再按切题25%、有效性35%、语气15%、事实25%计算；质量状态先看风险，再看总分80和有效性2的阈值。权重不代替门控。 |
| 哪些情况评不准？ | 上下文省略、代词指代、系统真实操作权限不明、隐含情绪、参考标签主观或矛盾、没有业务证据、规则未抽取出的断言。已见20条样本不代表真实总体，缺少人工数值评分也无法验证总分准确率。 |

综合分为 `100 × Σ(可评权重 × 维度分/4) / Σ(可评权重)`。事实 N/A 时只按剩余75%权重归一化，显示为暂定分。证据覆盖率为“有支持或矛盾证据的抽取断言数 / 抽取断言总数”，没有抽取断言时不伪造为100%。

## 严重程度与评分锚点示例

“怎么退货”得到清楚的步骤可以有效；“操作不了退货”再次得到同一套步骤则没有定位卡点。问“这两款哪个更好”时，先问预算和用途已经有价值；缺少具体型号属于另一项需明确的条件，不能直接判定回答完全无用。中性商品咨询无须安抚，但用户“连续收到破损商品”应考虑特殊经历。

输出同时保存用户任务、情绪原文、下一步状态、四维分数、逐维理由、问题标签、严重程度和建议，支持复核分数与理由是否自洽。

## 维度归属

| 观察 | 归属 | 不应连带处罚 |
|---|---|---|
| 问进度却只列一般时效 | 有效性；可能有通用回答/缺追问标签 | 不因没道歉扣语气 |
| 对象不明时先问需求、预算 | 已有效推进；遗漏具体对象可以是轻微缺口 | 不把未最终答出结果视为偏题 |
| 用户已卡在流程仍重复全流程 | 核心诉求理解与有效性；意图错配 | 不因有流程文字自动给高分 |
| 中性问规则，回复清楚且尊重 | 正常高语气分 | 不强制道歉或额外承诺 |
| 连续受损、恐惧、敏感需求 | 评估针对情境的回应 | 不以补偿金额衡量共情 |
| 具体承诺缺业务证据 | 待核实及风险队列 | 不等同于已证实幻觉 |

## 严重程度

- minor：已存在有效路径，缺少辅助细节、偏好或更好表达；通常有效性 3 分。
- major：核心处理被阻碍，用户必须重新求助或补齐关键对象才能推进；通常有效性 ≤2 分。
- 事实硬门控：有可信证据证明错误，或规则确认内部流程冲突；保留原门控，不交由模型自证。

严重程度、评分和下一步状态分别保存。程序检查下一步状态与有效性分数是否矛盾、共情标签是否缺少情绪原文，并产生复核信号，不悄悄替模型改成期望分数；更复杂的严重程度判断仍需人工复核。

## 标注与实验纪律

人工注释常只列主要问题，因此已有负标签不一定是全面排除；分歧需要复核。当前样本已全部见过，新版属于开发集上的回顾性改进，不能当独立泛化结果。旧标签文件 SHA-256 随实验记录保存，保证版本对比使用同一标签。

人工构造行为测试提前固定，覆盖中性咨询、已经卡住、主动澄清、明确侮辱、未知事实及回复内指令干扰。评估规则是分数区间、必要/禁止标签和配对顺序，不是凭文字相似度打分。这些也属于开发测试，不是独立专家金标准。
