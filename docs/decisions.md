# 设计决策与修订记录

## D04 · 用户反馈后：混合架构取代纯规则主线

用户提出规则 + LLM + 人工校准，以及参考回复成对对比，更符合 NLP 方向。采纳为 v2：规则保留为基线和严重风险约束；新增真实 API 语义裁判、明确标识的动态 mock、多标签校准、独立参考差异模块。参考差异的结果不回流到主评分。没有 API 时只能验证工程链路，不能宣称已验证真实 LLM 效果。

## D01 · 实施前：选择可复现规则基线

当前没有模型 API 配置和业务证据库。采用透明的规则评估器，真实读取输入并计算结果，不用预填 mock 分数。代价是语义覆盖有限，须在 UI、报告、README 中明确模式。真实 LLM 是后续增强项。

## D02 · 实施前：事实维度允许弃权

将“无证据”一律扣为幻觉，会系统性误伤附件中的正确回复；照抄人工参考又会引入证据泄漏。使用支持/矛盾/待核实三态，缺失时综合分只表示已评维度，并明确覆盖率。

## D03 · 实施前：不伪造数值金标准

附件没有人工分数。仅从定性分析整理服务缺口标签，公布争议案例和排除原因，并计算有限任务的一致性指标。所有数据已被开发者看过，结果不属于盲测。

## D05 · 实现检查：区分“要求自查”和“请求补充信息”

首次规则运行发现“请您检查优惠券的使用规则”被宽松匹配为已追问信息，导致漏掉具体定位需求。将请求模式收紧到提供、告诉、描述及实际问句，并增加反例测试。这是语义规则局限的具体例子，也是保留真实 LLM 层的理由。修正不改变人工标签或 LLM 提示词。

## D06 · 实现检查：合并重叠候选断言

LLM 可能补充规则句段中的一小段事实，重复计数会夸大待核实数量。对包含关系的片段进行去重，优先保留已有句段，报告明确断言不是原子事实级单位。该处理会低估一个句段中多个事实的数量，但优于重复累加；后续可改为实体-属性-值级断言抽取。

## D07 · 真实实验后：保留分歧，不以调分制造优越性

真实混合评估 Micro F1 为 0.6567，规则基线为 0.7869。开发者已见全部样本，规则对题内样本适配更强，标签也有主观边界；不应为了展示好看在这批标签上反复调提示词。保留完整结果、误判分析与基线对照，把混合架构定位为可校准系统，而非已经验证优于规则的产品。

## D08 · 真实实验：严格拒绝不合结构的模型输出

20 条主评分成功，参考对比最后一条初次输出字段不合协议，被拒绝。重运行通过内容缓存保留前 39 个结果，仅重试该条；通过后完成。未把失败输出悄悄修成预期结论，也未降级为 mock。

## D09 · v3：先固定标准与对照，再增加 Agent

将服务任务判断放在维度评分之前，细化轻微缺口/处理受阻，区分普通咨询与明确情绪需求。冻结旧提示词、原结果与两份标签；另预先固定10条构造行为样例。实际以同一模型分别评估两版，保留全部输出；没有改变标签来迎合新版。

## D10 · v3：如实报告精确率与召回率的取舍

精确率0.5946→0.75，召回率0.7333→0.60，Micro F1只从0.6567升至0.6667。误报减少，但共情正例漏检更明显。保留这次修订作为更明确、可复核的标准，不宣称全面优于旧版；下一轮需要额外人工复核和未见业务样本。

## D11 · Agent：结构化工具循环与最终输出核对

真实模型调度评估、查询、校准、证据表单和导出工具。首次工具流程验收通过后，人工查看发现答复把4分制写成4/5，说明“调对工具”不等于“解释全对”。增加明确分母、案例引用约束和已知分母错误检测；保留旧验收文本供审计，最终结果另存。

一轮真实调用还出现 finish 缺少 brief 的情况。brief 只用于展示下一步，因此将其调整为结束动作的可选字段；执行工具仍要求该字段。工具参数和真实答案未被补造。其余不合法动作最多要求重新输出两次，继续失败就停止。

## D12 · Agent：证据更新与报告一致性

人工证据按会话、案例和断言隔离，重算规则约束并保留来源；不修改原附件或全局报告。证据改变和新数据导入都会撤下旧报告入口，要求重新导出。主页面的固定报告明确标注为题目样例报告，避免与新数据混淆。
